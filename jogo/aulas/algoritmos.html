CONCEITO

Por que contar passos, e não segundos?

O mesmo programa roda em 1 s num notebook e em 0,1 s num servidor. O tempo em segundos depende da máquina. O que não muda é quantos passos o algoritmo dá quando a entrada tem tamanho n.

int soma(int[] v) {
  int s = 0;                 // 1 vez
  for (int x : v) s += x;    // n vezes
  return s;                  // 1 vez
}                            // total ≈ n + 2 passos

Se o vetor dobra, o trabalho dobra: o custo cresce linearmente → O(n).

Complexidade de tempo é a função que conta as operações básicas em função do tamanho n da entrada; a análise assintótica estuda seu comportamento para n grande.

DEFINIÇÃO

Big-O: um “teto” a partir de certo ponto

Exemplo: f(n) = 3n² + 5n + 2. Para n ≥ 1: 3n² + 5n + 2 ≤ 3n² + 5n² + 2n² = 10n². Com c = 10 e n₀ = 1 → f(n) = O(n²).

f(n) = O(g(n)) se existem constantes positivas c e n₀ tais que 0 ≤ f(n) ≤ c·g(n) para todo n ≥ n₀.
FOCO DO EDITAL

Por que usamos Big-O (O) e quase não cai Ω/Θ

Na análise de algoritmos, O(g) dá o teto assintótico ("cresce no máximo como g"). Para conhecimento de base, Ω(g) é o piso ("no mínimo") e Θ(g) é o sanduíche justo — mas o edital TJPB foca em análise assintótica e Big-O.

NotaçãoIdeiaExemplo com 3n² + 5n
O(g) — Big-OLimite superior ("no máximo")é O(n²) e tecnicamente também O(n³)
Ω(g) / Θ(g)Piso / justo (contexto teórico)piso Ω(n²); faixa justa Θ(n²)
Na prática da prova: pense quase sempre em Big-O no pior caso — "qual o crescimento dominante quando n explode?"

EXEMPLO RESOLVIDO

Calcule a complexidade, bloco a bloco

for (i = 0; i < n; i++) x++;                 // bloco A: n
for (i = 0; i < n; i++)
  for (j = 0; j < i; j++) x++;               // bloco B: 0+1+...+(n-1)
for (i = 1; i < n; i = i * 2) x++;           // bloco C: ≈ log₂ n
A = n+B = n(n−1)/2+C = log n→O(n²)

O bloco B parece “meio n²” porque j só vai até i. Mas n(n−1)/2 = 0,5n² − 0,5n: a constante 0,5 cai e continua sendo O(n²).

Dica: laço interno que depende do externo (j < i, j de i até n) → soma de PA → ainda n².

“Big-O significa pior caso e Ω significa melhor caso.”
O, Ω e Θ são limites de uma função. Dá para dizer “o pior caso é Θ(n)” e “o melhor caso é Θ(1)”: são coisas independentes.
RECURSÃO E ESPAÇO

Fibonacci ingênuo: recalcula tudo

fib(n) = fib(n−1) + fib(n−2). Veja as chamadas para fib(4): f(2) é calculado duas vezes (em vermelho).

Ingênuo: nº de chamadas cresce exponencialmente → O(2ⁿ) (cota superior).
Com memorização (guardar resultados) ou laço: O(n).

Espaço também conta: fatorial recursivo empilha n chamadas → O(n) de memória na pilha; o laço usa O(1).

RESUMO

Cola de bolso do capítulo

Pergunta mágica: “Se n dobrar, o trabalho faz o quê?”Não muda → O(1) · soma 1 passo → O(log n) · dobra → O(n) · quadruplica → O(n²) · eleva ao quadrado → O(2ⁿ).
  • Big-O conta passos em função de n; constantes e termos menores caem.
  • O = teto, Ω = piso, Θ = os dois (justo).
  • Sequência soma (vence o maior); aninhamento multiplica; dividir ao meio dá log n.
  • Melhor/médio/pior caso são cenários; O/Ω/Θ são limites — não confunda.
  • Recursão gasta memória de pilha; memorização derruba Fibonacci de exponencial para O(n).
TESTE RÁPIDO

Mostre que aprendeu

1) Qual a complexidade de f(n) = 7n log n + 20n + 3?

O(n log n) n log n domina n e a constante; o 7 cai.

2) Dois laços aninhados de 0 a n, seguidos de um laço de 0 a n. Complexidade?

O(n²) n² + n: fica o termo dominante.

3) (FGV-estilo) “Se um algoritmo é O(n), então ele também é O(n²).” Certo ou errado?

Certo O é cota superior; se cabe sob n, cabe sob n² (para n ≥ 1). Mas ele não seria Θ(n²).

4) Um laço faz i = n e, enquanto i > 1, executa i = i / 2. Complexidade?

O(log n) Cada volta corta i pela metade: cerca de log₂ n voltas.

🚂
Analogia do dia: vetor é um estacionamento com vagas numeradas (vá direto à vaga 7). Lista encadeada é um trem: cada vagão só sabe quem vem depois. Pilha é a pilha de pratos, fila é a fila do banco e a tabela hash é o armário de escaninhos com o nome na porta.
VETOR (ARRAY)

Vetor: vagas lado a lado na memória

Endereços (int de 4 bytes): posição i fica em base + i × 4. Um cálculo e pronto: acesso v[i] em O(1).

Mas para inserir no início é preciso empurrar todo mundo uma casa para a direita:

Vetor: acesso por índice O(1); inserção/remoção no início ou no meio O(n) (deslocamento). Em vetor dinâmico (ArrayList), inserir no fim é O(1) amortizado.
LISTA ENCADEADA

Lista encadeada: nós e ponteiros

Cada nó guarda um valor e o endereço do próximo. O último aponta para null. Os nós podem estar espalhados na memória.

Inserir no início: novo.próx = head; head = novo → O(1), ninguém é deslocado.
Achar o 3º elemento: tem que andar head → 12 → 7 → 3 → O(n). Não existe “pular” para o meio.

Duplamente encadeada: cada nó tem também o ponteiro para o anterior:

PASSO A PASSO

Inserir o 9 depois do 7 (a ordem importa!)

Passo 1. Temos 12 → 7 → 3 e um ponteiro p para o nó 7.

Passo 2. Crie o nó 9 e faça novo.próx = p.próx (o 9 passa a apontar para o 3). A lista ainda está inteira.

Passo 3. Agora p.próx = novo: o 7 aponta para o 9. A seta antiga (vermelha) some. Custo: O(1).

Fazer primeiro p.próx = novo: você perde o endereço do 3 e o resto da lista “some”.
Primeiro ligue o novo ao sucessor; depois ligue o antecessor ao novo.
PILHA (STACK)

Pilha = LIFO: o último a entrar é o primeiro a sair

Passo 1. push(3): o 3 entra no topo.

Passo 2. push(7): o 7 fica em cima do 3.

Passo 3. push(5): o 5 é o novo topo.

Passo 4. pop() → devolve 5: sai o ÚLTIMO que entrou (LIFO).

Passo 5. push(9): o 9 vira o topo.

Passo 6. peek()/top() → devolve 9 SEM remover. Pilha final (base → topo): 3, 7, 9.

push, pop e peek: todos O(1). Usos: desfazer (Ctrl+Z), pilha de chamadas de funções, parênteses balanceados e avaliação de expressões pós-fixas.

PILHA EM AÇÃO

Avaliando a expressão pós-fixa 5 3 + 2 *

Regra: número → empilha. Operador → desempilha dois (o 1º que sai é o operando da direita), calcula e empilha o resultado.

LidoAçãoPilha (base → topo)
5push 5[5]
3push 3[5, 3]
+pop 3, pop 5 → 5 + 3 = 8 → push[8]
2push 2[8, 2]
*pop 2, pop 8 → 8 × 2 = 16 → push[16] ✓

Em notação infixa, isso é (5 + 3) × 2 = 16. Parênteses balanceados usam a mesma ideia: abre → empilha; fecha → o topo tem que ser o par certo. “( [ ] )” ✓; “( ]” ✗.

FILA (QUEUE)

Fila = FIFO: o primeiro a entrar é o primeiro a sair

Passo 1. enqueue(A): A entra no fim (e, sozinho, também é a frente).

Passo 2. enqueue(B): B entra atrás de A.

Passo 3. enqueue(C): C entra no fim.

Passo 4. dequeue() → devolve A: sai o PRIMEIRO que entrou (FIFO).

Passo 5. enqueue(D): D entra no fim. Fila final (frente → fim): B, C, D.

enqueue (no fim) e dequeue (na frente): O(1) com lista encadeada ou vetor circular. Usos: fila de impressão, escalonamento de tarefas, buffers, atendimento.

“Fila de prioridade é uma fila FIFO.”
Na fila de prioridade sai o de maior prioridade, não o mais antigo. Costuma ser implementada com heap (cap. 3).
TABELA HASH

Tabela hash: a chave diz onde guardar

A função hash transforma a chave num índice: 10 mod 7 = 3, 22 mod 7 = 1. Para buscar, recalcula-se h(chave) e vai-se direto ao balde → O(1) em média. Mas 31 mod 7 = 3 também: colisão.

Tabela hash mapeia chaves a posições por uma função de dispersão; busca, inserção e remoção têm custo médio O(1) e pior caso O(n).

Árvores Binárias, BST e Heaps

Analogia do dia: uma árvore é o organograma do tribunal: uma raiz no topo, cada chefe com seus subordinados e nenhum ciclo. O foco do edital está em árvore binária, BST, percursos e heaps (fora de grafos avançados)!

Árvore binária: cada nó tem no máximo 2 filhos (esquerdo e direito). Atenção: alguns livros contam altura em nós (aqui daria 4) — leia como a questão define.

BST

Árvore binária de busca: menores à esquerda, maiores à direita

Buscar 60: 60 > 50 → direita · 60 < 70 → esquerda · achou! 3 comparações, não 7. A cada nível descartamos uma subárvore inteira — é a busca binária “em forma de árvore”.

Em uma árvore binária de busca, para todo nó, as chaves da subárvore esquerda são menores e as da subárvore direita são maiores que a chave do nó.
PASSO A PASSO

Inserindo 50, 30, 70, 20, 40, 60, 80 e depois 65

Passo 1. Insere 50 numa árvore vazia: ele vira a raiz.

Passo 2. 30 < 50 → esquerda. 70 > 50 → direita.

Passo 3. 20: 20<50 → esq; 20<30 → esq. 40: <50, >30. 60: >50, <70. 80: >50, >70.

Passo 4. Inserir 65: 65>50 → dir; 65<70 → esq; 65>60 → dir de 60. São 3 comparações = altura do caminho.

Inserir = buscar até cair num “buraco” (null) e pendurar o novo nó ali como folha.

BALANCEAMENTO

Quando a árvore vira uma “lista”

Inserir 10, 20, 30, 40 (já ordenados): cada um vai à direita do anterior. Altura n−1 → busca O(n).

Árvore AVL: fator de balanceamento (altura esq. − altura dir.) ∈ {−1, 0, 1}; se sair disso, faz rotações. Altura O(log n).

“Toda árvore binária de busca garante busca em O(log n).”
Só as balanceadas (AVL, rubro-negra) garantem. BST comum: O(log n) em média, O(n) no pior caso.
HEAP

Heap: o maior sempre no topo

Árvore completa guardada num vetor: filhos de i ficam em 2i+1 e 2i+2; pai em ⌊(i−1)/2⌋.

Operação (max-heap)Custo

Regra: pai ≥ filhos. Não confunda com BST: aqui 20 está à esquerda e 30 à direita sem ordem entre irmãos — o percurso em ordem não sai ordenado.

FILA DE PRIORIDADE

Max-Heap × Min-Heap e Heapify na prática

Max-Heap

Pai ≥ filhos. Topo guarda o maior elemento (ex.: escalonamento por maior prioridade/urgência).

Min-Heap

Pai ≤ filhos. Topo guarda o menor elemento (ex.: timers, fila pelo menor prazo de vencimento).

PONTE COM BANCO DE DADOS

Árvore B e Árvore B+ (índices SQL)

Enquanto BST/AVL têm 2 filhos por nó (ideais em RAM), bancos em disco usam Árvores B / B+ com centenas de chaves por nó (altura 3–4 para milhões de linhas, reduzindo leituras de disco!).

  • Na Árvore B+, todos os ponteiros de registros ficam apenas nas folhas, encadeadas entre si — acelerando muito WHERE data BETWEEN ...!
  • Folhas todas na mesma profundidade: busca sempre balanceada em O(log n).
RESUMO

Cola de bolso do capítulo

Pergunta mágica: “Está balanceada?”Sim (AVL, rubro-negra, B+) → O(log n) garantido. Não sei / BST comum → O(log n) em média, O(n) no pior caso.
  • BST: esq. < nó < dir.; percurso em ordem sai ordenado.
  • Remover nó com 2 filhos: sucessor em ordem (menor da direita) ou antecessor.
  • Heap: pai ≥ filhos (max) ou ≤ (min); topo O(1), inserir/remover O(log n), filhos em 2i+1 e 2i+2.
  • Árvore B+: nós largos para disco; folhas encadeadas aceleram consultas por faixa.

Busca e ordenação

🃏

2. Os “lentos” O(n²)Bubble, selection e insertion.

🃏
Analogia do dia: você ordena cartas na mão pegando uma por uma e encaixando no lugar certo — isso é o insertion sort. E acha uma palavra no dicionário abrindo no meio e descartando metade — isso é a busca binária.
BUSCA BINÁRIA

Busca binária: olha o meio e descarta metade

Passo 1. Procurar 23. lo = 0, hi = 9 → mid = (0+9)/2 = 4. v[4] = 16 < 23 → o 23 só pode estar à direita: lo = 5.

Passo 2. lo = 5, hi = 9 → mid = 7. v[7] = 56 > 23 → descarta a direita: hi = 6.

Passo 3. lo = 5, hi = 6 → mid = 5. v[5] = 23 → achou em 3 comparações (a busca linear faria 6).

while (lo <= hi) {
  int mid = lo + (hi - lo) / 2;      // evita estouro de (lo+hi)
  if (v[mid] == x) return mid;
  if (v[mid] < x) lo = mid + 1; else hi = mid - 1;
}
return -1;                           // não achou

BUBBLE SORT

Bubble sort: o maior sobe como bolha

Início. Ideia: comparar vizinhos e trocar se estiverem fora de ordem. O maior “borbulha” para o fim.

Passada 1. 5 > 1 → troca.

Passada 1. 5 > 4 → troca.

Passada 1. 5 > 2 → troca.

Passada 1. 5 < 8 → não troca. O 8 (maior) está na posição final.

Passada 2. 1·4 ok; 4 > 2 → troca; 4·5 ok. Agora o 5 também está no lugar.

Passada 3. Nenhuma troca → com a flag “trocou?”, o algoritmo para. Por isso o melhor caso (já ordenado) é O(n).

Pior e médio: O(n²) comparações. Melhor (com flag, vetor já ordenado): O(n). Estável e in-place.

SELECTION SORT

Selection sort: escolhe o menor e põe no lugar

PassadaMenor do trecho restanteVetor após a troca
início—[64, 25, 12, 22, 11]

Sempre varre o resto para achar o mínimo: O(n²) comparações em todos os casos, mas no máximo n − 1 trocas.

“Selection sort é estável.”
A versão usual com trocas não é: em [2ᵃ, 2ᵇ, 1], o 1 troca com 2ᵃ → [1, 2ᵇ, 2ᵃ] e os dois 2 invertem de ordem.

MERGE SORT

Merge sort: divide ao meio, depois intercala

São ≈ log₂ n níveis de divisão e cada nível de intercalação mexe nos n elementos → O(n log n) sempre (melhor, médio e pior). Custo: vetor auxiliar → O(n) de memória extra. É estável.

QUICK SORT

Quick sort: particionar em volta do pivô (Lomuto)

Início. Pivô = último elemento (4). i marca o fim da zona “≤ pivô”, que começa vazia (i = −1). j percorre o vetor.

j=0: 7 > 4, nada. j=1: 2 ≤ 4 → i = 0 e troca v[0]↔v[1].

j=2: 1 ≤ 4 → i = 1 e troca v[1]↔v[2].

j=3,4,5: 6, 8, 5 > 4, nada. j=6: 3 ≤ 4 → i = 2 e troca v[2]↔v[6].

Fim. Troca v[i+1] com o pivô: 4 vai para a posição 3, definitiva. Recursão em [2, 1, 3] e em [8, 5, 7, 6].

Pivô divide bem (meio) → O(n log n) no melhor e no médio. Pivô sempre o menor ou o maior (ex.: vetor já ordenado com pivô no último) → partições n−1 e 0 → O(n²). Não é estável; in-place (pilha de recursão O(log n) em média).

PEGADINHAS

Como a FGV tenta te derrubar

“O quicksort é sempre O(n log n), por isso é o mais usado.”
É O(n log n) no caso médio; no pior, O(n²). É usado porque costuma ser rápido na prática.
“Merge sort ordena in-place, sem memória adicional.”
A versão clássica em vetor precisa de O(n) de memória auxiliar para intercalar.
“Insertion sort é sempre pior que merge sort.”
Em vetor quase ordenado (ou pequeno), o insertion chega a O(n) e vence. Algoritmos híbridos usam insertion em pedaços pequenos.
RESUMO

Cola de bolso do capítulo

Pergunta mágica: “Qual é o PIOR caso e ele é estável?”n log n sempre: merge (estável) e heap (não). n² no pior: quick, bubble, selection, insertion. n no melhor: insertion e bubble com flag.
  • Busca binária: vetor ordenado + acesso por índice; O(log n); pior ⌊log₂ n⌋ + 1 comparações.
  • Bubble: maior vai para o fim a cada passada; flag → melhor caso O(n).
  • Selection: O(n²) sempre, poucas trocas, não estável.
  • Insertion: ótimo para quase ordenado; estável.
  • Merge: O(n log n) sempre, O(n) extra. Quick: pivô ruim → O(n²).

CLASSE E OBJETO

Classe é o molde que define atributos (estado) e métodos (comportamento); objeto é uma instância da classe, criada em tempo de execução, com estado próprio.

Encapsulamento: o estado fica guardado

public class Conta {

    if (v <= 0 || v > saldo) throw new IllegalArgumentException();
    saldo -= v;                               // regra protegida
  }
  public double getSaldo() { return saldo; }
}

Herança (“é um”) e sobrescrita

Java: uma classe estende só uma classe (herança simples), mas pode implementar várias interfaces.

COMPARAÇÃO

Sobrescrita × sobrecarga

Sobrescrita (override)

class Gato extends Animal {
  @Override
  String falar() { return "Miau"; }
}

Mesma assinatura, na subclasse. Resolvida em tempo de execução (ligação dinâmica).

Sobrecarga (overload)

int somar(int a, int b)
double somar(double a, double b)
int somar(int a, int b, int c)

Mesmo nome, parâmetros diferentes. Resolvida em tempo de compilação.

“Métodos que diferem apenas no tipo de retorno caracterizam sobrecarga.”
Em Java isso não compila: a sobrecarga exige lista de parâmetros diferente (quantidade, tipo ou ordem).

SOLID

SOLID: cinco princípios, uma meta

SSingle Responsibility: um único motivo para mudar.
OOpen/Closed: aberto para extensão, fechado para modificação.
LLiskov Substitution: subtipo substitui o tipo base sem quebrar.
IInterface Segregation: interfaces pequenas e específicas.
DDependency Inversion: dependa de abstrações.

Reunidos e popularizados por Robert C. Martin (“Uncle Bob”). Objetivo: código fácil de mudar, testar e reaproveitar.

Macete: cada letra responde a um “cheiro”: classe faz tudo (S) · if/else por tipo crescendo (O) · subclasse que lança “não suportado” (L) · interface gorda (I) · new de classe concreta no meio da regra de negócio (D).
S e O

SRP e OCP na prática

SRP

RelatorioService calcula, formata em PDF e envia e-mail.
CalculadoraRelatorio · GeradorPdf · EnviadorEmail — cada uma com um motivo para mudar.

OCP

if (tipo == "VIP") ... else if (tipo == "SERVIDOR") ...

interface Desconto { double aplicar(double v); }
class DescontoVip implements Desconto { ... }
// novo tipo = nova classe, sem editar as antigas
SRP: uma classe deve ter um, e apenas um, motivo para mudar. OCP: entidades de software devem estar abertas para extensão, mas fechadas para modificação.
L

Liskov: o Quadrado que quebrou o Retângulo

Matematicamente, quadrado “é um” retângulo. Mas em comportamento, não: quem usa Retângulo espera alterar largura e altura de forma independente.

Princípio da Substituição de Liskov: objetos de uma superclasse devem poder ser substituídos por objetos de suas subclasses sem alterar a correção do programa.
I e D

ISP e DIP: interfaces magras e setas invertidas

ISP: em vez de Multifuncional { imprimir(); escanear(); enviarFax(); }, crie Imprimivel, Escaneavel… A impressora simples implementa só o que usa.

“DIP e injeção de dependência são a mesma coisa, e exigem um framework.”
DIP é o princípio (depender de abstrações). Injeção de dependência é uma técnica para aplicá-lo — dá para fazer à mão, passando a dependência no construtor.
RESUMO

Cola de bolso do capítulo

Pergunta mágica: “Se eu precisar mudar isso amanhã, quantas classes vou ter que abrir?”Muitas → provavelmente algum princípio SOLID foi violado.
  • Encapsulamento (private + métodos), herança (“é um”), polimorfismo, abstração.
  • Sobrescrita = subclasse, execução; sobrecarga = parâmetros diferentes, compilação.
  • Java: 1 superclasse, várias interfaces; interface tem default/static desde o Java 8.
  • Prefira composição a herança; alta coesão, baixo acoplamento.
  • S um motivo · O estender sem editar · L substituir sem quebrar · I interfaces magras · D depender de abstrações.
